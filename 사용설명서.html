Claude Code 모드 5종

Claude Code를 더 빠르고 저렴하게 쓰게 해주는 5가지 추가 기능입니다. 입력창 위에 상태를 보여주고, 오래 걸리는 작업·로그인·단계 계획·코드 검사를 대신 챙겨 줍니다.

왜 만들었나

지난 30개 Claude Code 세션 기록을 집계해 보니, 비용과 시간이 새는 곳이 분명했습니다.

약 1,000만 토큰1시간 넘게 쉬었다가 다시 질문할 때 캐시가 만료되어 대화 전체를 다시 기록한 양. 전체 캐시 기록의 74%, 입력 비용의 약 30%(추정).
92회 + 30회오래 걸리는 작업을 Claude가 직접 감시(Monitor, sleep 루프). 깨울 때마다 약 23만 토큰을 다시 읽음.
140 : 15파일 수정 대비 검사 횟수. 같은 파일을 8~11번 고치거나, 커밋하지 않은 변경이 33시간 쌓인 경우도 있었음.

여기에 로그인·인증 단계마다 "확인해줘"를 주고받는 왕복, P1→P2→P3 단계를 매번 직접 지시하는 수고가 더해졌습니다. 다섯 모드는 이 다섯 가지를 하나씩 해결합니다.

설치하기

필요한 것: Claude Code 2.1.29x 이상(데스크탑 앱의 Code 탭 또는 터미널 claude). 모드는 사용자 폴더 ~/.claude/skills/에 넣으면 새 세션부터 자동으로 켜집니다. 별도 설정 파일은 바꾸지 않습니다.

방법 A — Finder로 복사 (권장, 권한 설정 불필요)

  1. 이 폴더의 mods 안에 있는 다섯 폴더(context-band, job-watch, handoff, plan-track, change-check)를 선택합니다.
  2. 새 Finder 창에서 ⇧⌘G를 누르고 ~/.claude로 이동합니다. 안에 skills 폴더가 없으면 만듭니다.
  3. 다섯 폴더를 ~/.claude/skills/ 안으로 복사합니다.
  4. Claude Code에서 새 세션을 엽니다. 입력창 위에 Context 막대가 보이면 설치 완료입니다.

방법 B — 설치 스크립트

sh "이 폴더 경로/install.sh"

다섯 모드를 ~/.claude/skills/로 복사하고 각각 검사(claude plugin validate)합니다. 다시 실행하면 최신 버전으로 덮어씁니다.

"Operation not permitted"가 나오면: macOS가 터미널의 iCloud Drive 접근을 막은 것입니다. 방법 A를 쓰거나, 시스템 설정 → 개인정보 보호 및 보안 → 파일 및 폴더 → 터미널에서 iCloud Drive 접근을 켠 뒤 터미널을 다시 열고 실행하세요. 또는 폴더를 다운로드 폴더 등으로 먼저 옮긴 뒤 실행해도 됩니다.

설치 확인 · 끄기 · 제거

claude plugin list                          # context-band@skills-dir 등 5개가 ✔ loaded
claude plugin disable job-watch@skills-dir  # 끄기 (enable 로 다시 켜기)
rm -r ~/.claude/skills/job-watch            # 완전히 제거

화면 한눈에 보기

모드들은 입력창 바로 위 띠(밴드)에 한 줄씩 나타납니다. 할 일이 없으면 그 줄은 보이지 않습니다. 위에서부터 다음 순서로 쌓입니다(순서는 설치 환경에 따라 조금 다를 수 있습니다).

1. context-band — 캐시·컨텍스트 가드

지금 대화가 얼마나 큰지, 캐시가 언제 만료되는지 항상 보여주고, 비싼 재기록이 일어나기 직전에 선택지를 줍니다.

화면

요소의미
막대 + 435.9k / 1.0M (44%)현재 사용량 / 전체 용량. 응답이 끝날 때마다 갱신(로컬 추정이라 API 호출 없음).
░ Free space남은 공간. 항상 표시되며, 다른 칸에 마우스를 올리면 그 항목이 앞에 추가로 나타납니다.
캐시 47분마지막 응답 후 1시간 캐시가 남은 시간. 10분 이하 주황, 지나면 빨간 "캐시 만료".
압축컨텍스트가 20만 토큰을 넘으면 나타남. /compact와 같은 압축.
인계 노트현재 대화를 요약한 Handoff.md를 세션 폴더에 쓰고, 새 세션 첫 메시지를 클립보드에 복사.

캐시 만료 시 전송 보류

1시간 넘게 쉬었다가, 컨텍스트가 10만 토큰 이상인 상태에서 메시지를 보내면 전송을 잠시 멈추고 둘째 줄이 바뀝니다.

  • 그대로 보내기 — 재기록 비용을 감수하고 원래 메시지를 보냅니다.
  • 압축 후 보내기 — 대화를 먼저 압축해 재기록 양을 줄인 뒤 보냅니다.
  • 취소 — 보내지 않고 입력창에 글을 되돌립니다. 이때 인계 노트로 새 세션을 시작하는 것도 좋은 선택입니다.

휴대폰 등 다른 기기에서 보낸 메시지, 예약 작업, 이미지·파일이 첨부된 메시지는 멈추지 않고 바로 보냅니다.

작동 방식

인계 노트(Handoff.md)로 새 세션 이어가기

  1. 인계 노트를 누릅니다. 버튼이 "인계 노트 작성 중…"으로 바뀝니다(수 초~1분).
  2. 세션 폴더에 Handoff.md가 생깁니다. 목표 · 현재 상태 · 완료한 일 · 남은 일 · 결정 사항과 제약 · 관련 파일과 경로 · 주의할 점 · 새 세션 첫 지시로 구성됩니다. 기존 파일은 Handoff.prev.md로 보관됩니다.
  3. 클립보드에 "…/Handoff.md 를 읽고 이어서 진행해줘."가 복사됩니다. 같은 폴더에서 새 세션을 열고 ⌘V로 붙여 넣어 보내면 됩니다.

노트는 현재 대화를 캐시에서 그대로 읽어 따로 생성하므로, 대화에 새 턴이 추가되지 않고 비용도 일반 턴보다 적습니다.

조정할 수 있는 값

~/.claude/skills/context-band/hooks/register.tsx 맨 위 상수: CACHE_TTL_MS(캐시 수명, 기본 1시간), GUARD_MIN_TOKENS(보류 기준, 10만), COMPACT_HINT_TOKENS(압축 권장 기준, 20만). 계정이 5분 캐시를 쓰는 경우 카운트다운이 실제와 맞지 않을 수 있습니다.

2. job-watch — 작업 감시

백업·해시·인제스트처럼 오래 걸리는 작업을 Claude 대신 모드가 지켜보고, 끝나면 결과를 한 번만 전달합니다.

작동 방식

  1. Claude가 긴 작업을 시작한 뒤 watch_job 도구로 넘깁니다: 이름, 확인 명령, 완료 패턴(예: ALL DONE), 실패 패턴(예: ABORT), 확인 간격(기본 60초, 최소 15초).
  2. Claude는 바로 턴을 끝냅니다. 모드는 간격마다 확인 명령을 실행하고 작업 감시 창과 상태줄에 마지막 출력 줄·경과 시간·확인 횟수를 보여줍니다.
  3. 완료 패턴이 나오거나, 실패 패턴이 나오거나, 확인 명령이 3번 연속 실패하거나, 감시 시간(기본 24시간)이 끝나면 알림·데스크탑 알림을 띄우고 Claude에게 결과 메시지를 한 번 보냅니다.

사용하는 법

  • Claude에게 오래 걸리는 작업을 맡기면 자동으로 이 도구를 씁니다. 직접 지시해도 됩니다: "끝나면 알려줘, 감시는 job-watch로".
  • /jobs — 작업 감시 창 열기. 각 작업의 중지 버튼으로 감시를 멈출 수 있습니다(Claude에게는 알리지 않음).

사진 정리 세션 한 번에서 Monitor로 깨운 77회 × 약 25만 토큰 읽기가, 이 모드로는 완료 메시지 1회로 바뀝니다.

3. handoff — 사용자 액션 핸드오프

로그인·비밀번호·2FA·브라우저 승인처럼 사람만 할 수 있는 일을 입력창 위에 "할 일"로 띄우고, 끝났는지 확인까지 자동으로 해서 Claude에게 넘깁니다.

화면

  • 완료 — 확인 명령이 있으면 먼저 실행합니다. 성공하면 결과를 붙여 Claude에게 보내고 줄이 사라집니다. 실패하면 이유가 표시되고 버튼이 다시 확인 / 그래도 전달로 바뀝니다.
  • 자동 확인 — 확인 명령이 있으면 15초마다(최대 30분) 실행해서, 로그인이 끝나는 순간 버튼을 누르지 않아도 완료 처리합니다.
  • 취소 — Claude에게 아무것도 보내지 않고 줄을 지웁니다.

Claude는 사람이 해야 할 일이 생기면 메시지로 부탁하는 대신 request_user_action 도구로 이 줄을 만듭니다. 출력 붙여넣기와 "확인해줘" 왕복이 필요 없어집니다.

4. plan-track — 단계 진행 트래커

3단계 이상의 계획을 한 줄 진행 표시로 보여주고, 버튼 하나로 다음 단계를 지시합니다. 프로젝트 폴더별로 저장되어 새 세션에서도 이어집니다.

  • Claude가 계획을 제안하거나 내가 계획을 받아들이면 set_plan으로 등록하고, 단계마다 update_plan으로 표시를 바꿉니다.
  • 다음 단계(진행 중이면 계속) — "계획 ○○의 다음 단계 '3. …'를 진행해줘"를 내 메시지로 보냅니다. Claude가 응답하는 동안에는 숨겨집니다.
  • × / 닫기 — 계획을 지웁니다. 모든 단계가 끝나면 "모두 완료"와 닫기가 표시됩니다.
  • 같은 폴더에서 새 세션을 열면 진행 줄이 그대로 다시 나타나고, 계획 요약이 Claude의 지침에 짧게 들어가 대화를 다시 읽지 않아도 이어서 진행할 수 있습니다.

계획 요약은 세션이 시작될 때 한 번만 지침에 넣고 세션 중에는 바꾸지 않습니다. 지침이 중간에 바뀌면 대화 전체의 캐시가 무효화되기 때문입니다(1번 모드의 목적과 같음).

5. change-check — 코드 변경 확인

Claude가 수정한 파일을 응답이 끝날 때 자동으로 검사하고, 실패하면 버튼 하나로 오류를 넘깁니다. 오래 쌓인 미커밋 변경도 경고합니다.

수정한 파일검사
.pyPython 문법 검사(py_compile)
.sh .bash셸 문법 검사(sh -n)
.jsonJSON 파싱 검사
.js .mjs .cjsnode --check
.ts .tsx프로젝트에 TypeScript가 설치된 경우에만 tsc --noEmit (다운로드하지 않음)
프로젝트 명령지정하면(예: npm test) 위 검사 대신 실행. Claude에게 "이 프로젝트 검사는 npm test로 해줘"라고 하면 set_check_command로 저장되고 세션이 바뀌어도 유지.
  • 오류 전달 — 오류 내용을 붙여 "확인하고 고쳐줘"를 보냅니다. 고친 뒤 다음 응답이 끝나면 다시 검사합니다.
  • 통과 표시는 다음 메시지를 보내면 사라집니다. /check로 언제든 다시 검사할 수 있습니다.
  • git 프로젝트에서 변경이 있고 마지막 커밋이 24시간 이상 지났으면 미커밋 경고를 띄웁니다.
  • Edit·Write로 고친 파일만 추적합니다. sed 같은 셸 명령으로 고친 파일은 감지하지 않습니다.
  • 이 모드가 실패하더라도 파일 수정과 메시지 전송은 그대로 진행되도록 만들어져 있습니다.

문제 해결

증상해결
설치 후에도 아무것도 안 보임새 세션을 열어야 적용됩니다. claude plugin list에서 5개 모드가 ✔ loaded인지 확인하세요.
"Operation not permitted"터미널의 iCloud Drive 접근 권한 문제. 설치 방법 A(Finder 복사)를 쓰세요.
계획·할 일 줄이 안 보임등록된 계획이나 할 일이 있을 때만 나타납니다. 정상입니다.
막대 위에 마우스를 올려도 정보가 안 나옴마우스 이벤트를 전달하지 않는 터미널에서는 호버가 동작하지 않습니다. 숫자와 Free space는 항상 표시됩니다.
Context 막대가 두 개같은 모드가 두 위치에 설치된 경우입니다. claude plugin list로 중복을 찾아 하나를 지우세요.
캐시 카운트다운이 실제와 다름1시간 캐시 기준입니다. 5분 캐시 환경이면 CACHE_TTL_MS를 조정하세요.

구조와 수정

mods/<모드>/
├─ .claude-plugin/plugin.json   이름·버전·설명
├─ hooks/hooks.json             모듈 목록
├─ hooks/register.tsx           모드 본체
├─ types/index.d.ts             상태 타입
└─ tests/*.test.tsx             테스트
claude plugin validate ~/.claude/skills/context-band   # 구조 검사
claude plugin test ~/.claude/skills/context-band       # 테스트 실행

수정한 내용은 다음 새 세션부터 적용됩니다. 다섯 모드 모두 테스트(총 32개)를 통과한 상태로 배포됩니다.
